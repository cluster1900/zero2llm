# 旋转位置（P12）：RoPE 与 YaRN，能算更长不等于能读懂 {#p12-rope}

在 S0 / S1 中，我们给每个 token 加一个可学习的“座位号”向量。现在做 S2：删掉绝对位置表，在注意力的 Q、K 上旋转坐标。其余仍是多头注意力、LayerNorm、GELU 和 Pre-LN 残差，不能把下一章的升级一起混进来。

本章先让你用纸笔算一次旋转，再追踪缓存中的位置，最后亲眼看一个“训练长度内答对，长度外答错”的 CPU 小实验。配套 [code/13_rope.py](../code/13_rope.py) 实现的是**普通 RoPE，不是完整 YaRN，也不承诺获得生产级长上下文能力**。

## P12.1 不再给座位贴标签，而是转动方向

想象每个座位有一面小钟。Q 和 K 原本是指针，位置决定转多少角度。同样的两根指针，若一起多转一圈中的同一角度，它们的夹角不变；如果只移动其中一个座位，夹角就会改变。

这个比喻有两条边界。第一，真实 Q、K 不是二维，而是拆成许多二维坐标对，各对转速不同。第二，旋转不增加语义知识，也不使两个 token 越远就必然越不相关；内容投影和整个网络仍参与决定分数。

![RoPE：二维旋转保留长度；缓存追加时继续使用位置 3、4，只旋转新 Q/K。](assets/diagrams/p12-rope.svg)

S1 与 S2 的区别可以写成三行：

```text
S1：x = token_embedding + learned_position_embedding → Q/K/V → 注意力
S2：x = token_embedding → Q/K/V → 对 Q/K 做 RoPE → 注意力
                              V 不旋转；不再增加绝对位置表
```

换掉位置机制会改变模型函数，不能声称 S1 与 S2 用同一份权重就有相同输出。本章证明的是 **S2 自己的完整前向与缓存前向使用同一个模型、同一组参数时对齐**。

## P12.2 先把一个二维旋转算完

二维向量 `[a,b]` 逆时针旋转角度 φ 后：

```text
a' = a cosφ − b sinφ
b' = a sinφ + b cosφ
```

这里是弧度：π/2 等于 90°。取 `[a,b]=[3,4]`，原长度是 √(3²+4²)=5。

### 表 P12-1：旋转方向变了，长度没有变

| φ | cosφ | sinφ | 旋转结果 | 长度 |
| --- | --- | --- | --- | --- |
| 0 | 1 | 0 | [3,4] | 5 |
| π/2 | 0 | 1 | [-4,3] | 5 |
| π | -1 | 0 | [-3,-4] | 5 |

以第二行为例：第一坐标是 3×0−4×1=−4；第二坐标是 3×1+4×0=3。浮点 cos(π/2) 未必严格等于 0，因此测试使用小容差，不要求每一位相等。

为什么长度不变？把 a'²+b'² 展开，交叉项互相抵消，剩下 `(a²+b²)(cos²φ+sin²φ)=a²+b²`。这不是“训练出来大致如此”，而是旋转公式的性质。源码 `rotation_walkthrough()` 用 float64 生成上表，`test_rotation_matches_independent_float64_matrix_and_preserves_tail` 还用独立的 2×2 矩阵验证实现，防止完整前向与缓存路径一起写错却互相对齐。

## P12.3 为什么位置差会进入注意力分数

把位置 m 的旋转记作 R(mθ)，θ 是这一对坐标每前进一个 token 的转角。RoPE 对 Q、K 分别使用自己的位置：

```text
q_rot = R(mθ) q
k_rot = R(nθ) k
q_rot · k_rot = q · R((n−m)θ) k
```

“两个都转”可改写成“第一个不转，第二个只转相对角度”。这就是点积中的相对位置性质。注意：公式把 q、k 当作固定的内容向量；真实 q、k 由上下文产生，不能据此说整个模型输出只由距离决定。

令 q=[1,2]、k=[3,4]、θ=1，设 Δ=n−m。直接代入会得到：

```text
q · R(Δ)k
= 1×(3cosΔ−4sinΔ) + 2×(3sinΔ+4cosΔ)
= 11cosΔ + 2sinΔ
```

### 表 P12-2：同时平移位置，固定内容的点积不变

| m | n | Δ=n−m | 旋转后点积 |
| --- | --- | --- | --- |
| 0 | 1 | 1 | 7.626267334 |
| 2 | 3 | 1 | 7.626267334 |
| 0 | 2 | 2 | -2.759020348 |

前两行是把两个位置都加 2；最后一行改变了相对距离。表由同一个脚本生成。更大距离下三角函数还会继续摆动，因此**不能从这个表归纳出“距离越大，点积就单调减小”**，更不能把 RoPE 说成一个自动削弱远距离内容的开关。

## P12.4 多维向量：不同坐标对像不同转速的钟

设每个头宽度为 d，实际旋转的前 r 个坐标称为 `rotary_dim`。r 必须为正偶数，且不超过 d。本章默认 r=d；部分旋转时，后面 d−r 个坐标保持原样。

我们使用相邻配对：`(x0,x1)、(x2,x3)、…`。对第 i 对，i 从 0 开始：

```text
θ_i = base^(−2i/r)
φ_i(p) = p × θ_i
```

`base=10000` 是本例的设定，不是所有模型统一的常数。r=8 时有四对，而不是八对。位置 p=10 时：

### 表 P12-3：快钟和慢钟

| i | 坐标对 | θ_i：每 token 转角 | p=10 的角度 | 转一圈所需 token 数 2π/θ_i |
| --- | --- | --- | --- | --- |
| 0 | 0,1 | 1.000000 | 10.000000 | 6.283185 |
| 1 | 2,3 | 0.100000 | 1.000000 | 62.831853 |
| 2 | 4,5 | 0.010000 | 0.100000 | 628.318531 |
| 3 | 6,7 | 0.001000 | 0.010000 | 6283.185307 |

这是 `frequency_walkthrough()` 的输出。高频意味着转得快、波长短；低频意味着转得慢、波长长。不能把“低频坐标编号大”误读成“绝对位置大”。

有些实现将前半和后半坐标配对，而不是相邻配对。只要权重排列和旋转约定配套，二者可以通过相应的维度置换对应；**不能把已有 checkpoint 的权重原样交给另一种配对约定，假装没有改变模型**。本章不用外部 checkpoint。

`apply_rope` 的核心代码与上面的两行算式一一对应：

```python
frequencies = base ** (-torch.arange(0, dim, 2, device=x.device, dtype=work_dtype) / dim)
angles = positions.to(work_dtype)[:, None] * frequencies[None, :]
c, s = angles.cos(), angles.sin()
even = x[..., :dim:2].to(work_dtype)
odd = x[..., 1:dim:2].to(work_dtype)
rotated = torch.stack((even * c - odd * s, even * s + odd * c), dim=-1)
rotated = rotated.flatten(-2).to(x.dtype)
return torch.cat((rotated, x[..., dim:]), dim=-1)
```

第一行生成 r/2 个频率；第二行把 T 个位置与这些频率相乘，得到 `[T,r/2]` 角度表。`stack` 放回两个坐标，`flatten` 恢复最后一维。`x` 可为 `[B,H,T,d]`，角度表会广播到 batch 和头上。完整函数检查维度、偶数、位置长度及设备。

float64 输入用 float64 计算角度；float16/bfloat16 先转 float32 计算旋转再转回，避免直接在低精度里算角度。本实现没有声称任意大位置都足够精确，float32 也有数值范围和分辨率限制。

## P12.5 S2 的张量账本和接口

本章的 `RopeConfig` 前五个字段沿用 S0：词表大小、主干宽度、头数、层数、允许的最大输入长度；新增 `rope_base` 与可选 `rotary_dim`。例如 `RopeConfig(17,16,4,2,64)` 表示 17 个 token、宽度 16、4 个头、2 层、最多 64 个位置。每头宽度 d=4。

| 步骤 | 本例 B=2、T=12 时的形状 | 操作 |
| --- | --- | --- |
| ID | [2,12] | token 查表 |
| x | [2,12,16] | 没有 `pos_emb` 相加 |
| Q、K、V | 各 [2,4,12,4] | 线性投影后分头 |
| 旋转后 Q、K | 各 [2,4,12,4] | 形状不变，V 不变 |
| scores | [2,4,12,12] | QKᵀ / √4，再加因果 mask |
| Attention 输出 | [2,12,16] | 对 V 加权、拼头、输出投影 |
| logits | [2,12,17] | 各 Block 后接归一化和词表分类头 |

`RopeGPT(config).forward(idx, targets=None)` 返回 `(logits,loss)`。传入右移标签时 loss 是所有位置的平均交叉熵；没有标签时 loss 为 None。LayerNorm 和 GELU 没有偷偷替换，KV 头也没有共享。后两章在这份基线上分别做 S3、S4。

完整前向会生成 `positions=0,…,T−1`，分别旋转 Q 与 K；缓存前向则必须沿用已有位置。下一节就是二者最容易分叉的地方。

## P12.6 缓存 offset：旧钥匙不能再转一次

已有 P=3 个 token，新来 C=2 个，位置应该是 **[3,4]**，不是 [0,1]。本例缓存保存**已经旋转的 K**，以及没有旋转的 V：

```python
positions = torch.arange(offset, offset + T, device=idx.device)
q = apply_rope(q, positions, attn.rope_base, attn.rotary_dim)
k = apply_rope(k, positions, attn.rope_base, attn.rotary_dim)
if cache is not None:
    k = torch.cat((cache.layers[i][0], k), dim=2)
    v = torch.cat((cache.layers[i][1], v), dim=2)
```

每层都这样做，不能只修第一层。旧 K 保持原样；对拼接后的所有 K 再整体旋转，会把旧位置转两次。

RoPE 也不能代替因果 mask。P=3、C=2 的 mask 仍是：

| query 位置 | key0 | key1 | key2 | key3 | key4 |
| --- | --- | --- | --- | --- | --- |
| 3 | 看 | 看 | 看 | 看 | 不看 |
| 4 | 看 | 看 | 看 | 看 | 看 |

`key_position <= query_position` 使用真实整数位置。缓存内存仍是 MHA 的 `2×层数×B×H×T×d×每元素字节数`。上节 2 层、B=2、H=4、T=12、d=4、float32 的结果为 **6144 字节**。去掉绝对位置表并不会把历史 K/V 也去掉；这是张量有效载荷，不包含 Python 对象、分配器和注意力中间结果。

本接口只支持无 padding、同长度 batch、固定位置规则、eval 模式。新请求必须传 `cache=None`。缓存与模型绑定，参数更新/替换、dtype 改变、RoPE 配置改变、归一化 epsilon 改变等都会使旧缓存失效；实现检查这些签名并报错。缓存张量必须当作只读对象，不支持通过 `.data` 偷改参数绕过版本计数。

完整前向与分块前向对照了逐 token、[3,4,2,3] 分块、一次完整输入以及 T=1。脚本种子 42、float32 下最大绝对误差实测为 **2.38418579×10⁻⁷**；另有 float64、部分旋转、不同 batch、请求重置、缓存分支与因果性测试。不是拿“生成了相同的字”替代所有 logits 的比较。

## P12.7 外推和插值：可以继续转，但没学过新路程

没有绝对位置查表，并不表示长上下文问题消失了。公式当然能给位置 1000 算 cos/sin；模型是否学会在那个距离检索内容，是另一个问题。新增干扰内容、注意力分布、训练数据和数值精度也都会影响结果。

设训练长度 L=8，希望使用长度 L′=32，扩展倍数 s=L′/L=4：

- **直接外推**：仍用 pθ，不改变转速；测试会出现训练未覆盖的相对距离。
- **位置插值（PI）**：用 `(p/s)θ`，等价于把频率改为 θ/s。这里缩放的是旋转相位，不是删除 token，也不是把注意力矩阵缩成八个位置。

### 表 P12-4：同一个位置，新的转角

| token 位置 p | 外推的 pθ | PI 的 (p/4)θ |
| --- | --- | --- |
| 0 | 0θ | 0θ |
| 7 | 7θ | 1.75θ |
| 8 | 8θ | 2θ |
| 31 | 31θ | 7.75θ |

表由 `interpolation_walkthrough()` 生成。通常以长度比 L′/L 缩放，因此最后的 7.75 不等于训练最后一个整数位置 7；这是长度定义和离散端点的区别，不能声称端点逐一重合。相邻 token 的相位差也从 θ 压缩成 θ/4，可能改变模型对局部距离的分辨。因果 mask 仍比较原始的 token 次序，不随 PI 缩放。

只修改 `max_seq_len`，只是放开本实现的输入检查；只做 PI，也不能自动证明质量改善。需要指定训练方案，并分别测短上下文和目标长上下文。本章不把 PI 数值示范当作已训练的位置扩展模型。

## P12.8 YaRN：按频段调节，还要调注意力分数

[YaRN 原论文 v2，§3.2–3.4](https://arxiv.org/html/2309.00071v2) 的组合不只是“把位置除以 s”。用波长 λ=2π/θ，与原训练长度 L 的比值 r=L/λ，来区分频段：

- 转得快、训练范围内已转过很多圈的频段：保留原频率。
- 转得慢的频段：使用 θ/s 插值。
- 中间频段：通过 ramp 混合 θ/s 和 θ，而非给所有维度同一个缩放。

论文定义的 ramp γ 从 0 过渡到 1，混合式为 `θ′=(1−γ)θ/s+γθ`；因此 γ=0 对应完全插值，γ=1 对应不改频率，方向不要写反。

另一部分是注意力温度：把 `softmax(QKᵀ/√d)` 改为 `softmax(QKᵀ/(t√d))`。若 Q 和 K 各乘 a=√(1/t)，点积会乘 **a²**，不是 a。论文对 LLaMA 系列给出的经验关系是 `a=1+0.1 ln(s)`，不能当成所有模型通用的常数。这个缩放会改变 Q/K 的长度；P12.2 的“范数不变”只适用于未附加幅度缩放的纯旋转。

频段插值与注意力缩放构成这里介绍的 YaRN 核心。训练和长文本评估仍需另外说明，本章没有做论文规模的微调。不要把本章普通 RoPE 的 CPU 结果标成“YaRN 复现”。

还有一个缓存陷阱：如果生成中动态改变 s，旧 K 所用的角度规则就过期。当前 S2 固定规则并拒绝改配置后复用旧缓存；它不实现 Dynamic YaRN。若要扩展，需要专门设计未旋转 K 的保留/重算等一致性策略，不能只改一个频率变量后继续拼旧 K。

## P12.9 CPU 反例：短距离记住了，长距离未必记得住

我们不拿三首诗自然语言输出评判长上下文，而是造一个明确任务：

```text
输入：[BOS=9, 答案a, 随机干扰token…, QUERY=8]
目标：在最后 QUERY 位置预测 a，a 只可能是 0、1、2、3
```

比如 `[9,2,7,0,6,1,3,8]` 的正确答案是 2。干扰 token 来自 0–7，可能包含其他候选答案，不能只找序列里唯一出现的某个符号。BOS 和 QUERY 帮助定义任务，没有泄露“最后一格应该猜什么”。

完整模型接口仍可做语言模型训练，但**这个实验只对 QUERY 位置的十分类 logits 算一次交叉熵**，不是全序列 next-token loss，不报告语言模型困惑度。只在四种合法答案里均匀猜，准确率基线是 25%；如果在十个输出 ID 中均匀乱猜，则是 10%。训练让模型学会使用合法答案，不应混淆这两条基线。

实验协议写死在 `length_experiment()`，便于复现和审计：

- CPU、float32、单线程；验证环境 PyTorch 2.14.1+cpu，依赖见仓库 requirements。
- 两层模型，d_model=32，H=4，词表大小 10；普通 RoPE、全头旋转、base=10000。
- 从一开始允许 `max_seq_len=64`，**实际训练样本始终只有 8 个位置**。
- AdamW，学习率 0.003，weight_decay=0；batch=32，更新 400 次，共 12800 个训练样本。
- 独立生成的测试流从未交给优化器；每个长度 512 个样本，标签仍是相同的 0–3，没有“长序列突然出现训练没见过的目标字”这一混淆。
- 完整报告种子 2025、2026、2027，不只挑一个最差的长长度；小型合成数据仍可能重复，独立抽样不等于自然文本去重测试。

**结论只到这里：这个设置在训练长度内成功，但直接外推后不能保持准确率。** 不是证明 RoPE 在所有长任务上都失败，也不是证明 YaRN 一定解决这个任务。增长长度同时增加检索距离和干扰 token 数，本实验没有隔离二者；也没有与其他位置方法做等预算对照，所以不能把全部损失归因于某一个频率。

尤其注意 T=64 常比 T=32 好。我们如实保留这个非单调现象，不把表改写成“长度越长越差”的漂亮故事。周期相位可能参与这种变化，但仅凭这张表不能确定原因；不同种子的变化也不小。算法能继续计算，是能力测试的起点，不是终点。

## P12.10 怎么运行，以及哪些检查比一句生成结果更可靠

在仓库根目录、已经安装 `requirements.txt` 的 Python 环境中运行：

```bash
OMP_NUM_THREADS=1 python code/13_rope.py
OMP_NUM_THREADS=1 python code/13_rope.py --skip-training
OMP_NUM_THREADS=1 python code/13_rope.py --seeds 2026
OMP_NUM_THREADS=1 python -m unittest discover -s tests -p 'test_rope.py' -v
```

第一条打印所有算术表、缓存差值和三个种子的训练/测试结果；第二条跳过训练；第三条只复现指定种子。没有权重下载，不需要 GPU。缺少 PyTorch 时 CLI 给出安装提示；测试沿用仓库的稳定 2.14.x 版本闸门，**被跳过不算通过**。不同硬件/数值库末位可能有差异，测试对记录值使用明确的 CPU 容差。

`tests/test_rope.py` 不只检查形状。它核对旋转范数、独立矩阵参考、相对位置恒等式、未旋转尾部、梯度有限性、float64 精度、缓存位置/因果 mask/内存/重置，以及训练反例的可复现指标。负例还故意重置新块 offset、取消旋转、把旧 K 转第二次，确认会被 logits 比较识别出来。规范正确性与模型质量是两套检查，两套都不能省。

## P12.11 自测与参考答案

先遮住答案，试着独立解释：

1. `[3,4]` 逆时针转 90° 后是什么？模长是多少？
2. q=[1,2]、k=[3,4]、θ=1，位置从 (0,1) 改为 (2,3)，点积会改变吗？为什么不能由此断言整个模型平移不变？
3. d=8、rotary_dim=6 时有几对旋转坐标？哪两个坐标原样保留？
4. 缓存已有 7 个 token，本次新增 3 个，RoPE 位置应是什么？旧 K 要不要重新旋转？
5. L=8 扩到 L′=32，用 PI 时位置 31 的相位是什么？一共有多少 token？
6. YaRN 若让 Q、K 都乘 a，注意力点积乘多少？纯旋转的范数测试还能原样用吗？
7. 本实验 T=64 比 T=32 好，是否推翻“只放宽长度检查不保证质量”？
8. 对 2 层、B=2、H=4、T=12、d=4 的 float32 模型，实际 K/V 有效载荷多少字节？

参考答案：

1. `[-4,3]`，模长仍为 5，见 `rotation_walkthrough()`。
2. 不变，都是 7.626267334，因为相对位置差仍是 1。结论固定了 q、k；上下文、边界和模型其他计算也可能变化。
3. 三对，即 (0,1)、(2,3)、(4,5)；坐标 6、7 不动。频率公式的分母使用旋转宽度 6。
4. `[7,8,9]`。旧 K 已经旋转，不再旋转；新 query 7 也不能偷看 key8/9。
5. `7.75θ`，仍有 32 个 token；最后 query 的原始位置仍是 31，不是“第 7 个 token”。
6. 乘 a²。附加幅度缩放后不再保持原范数，不能套用普通 RoPE 的单位旋转断言。
7. 不推翻。测试长度外仍低于 T=8 的准确率，而失败幅度不必随长度单调增长；我们没有证明某种普遍规律。
8. `2×2×2×4×12×4×4=6144` 字节。RoPE 不减少 KV 数量，也不等于没有缓存成本。
